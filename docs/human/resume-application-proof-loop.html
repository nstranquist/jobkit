JobKit 0.10.1 · private local workflow

Use the right verified resume. Keep the final send human.

JobKit can select a current nicos-resume artifact, verify every digest, copy it into an application package, and record why it made that choice. It never submits the application.

✓ Four sendable lanes · PDF, DOCX, and ATS text
1Recheck the posting
2Prove hard constraints
3Select a resume lane
4Build a review package
5Nico reviews and sends

One safe command

jobkit inbox recheck --all --json
jobkit inbox slate --platform 3 --fullstack 1 \
  --adoption 1 --stretch 0 --employer-cap 1 --json
jobkit apply-plan <inbox-id> --json

The default application artifact is a verified PDF from ~/dev/nicos-resume when its sendable index exists.

Explicit controls

--resume-artifact pdf|docx|ats
--resume-root /path/to/nicos-resume
--resume-root none

Use none to disable the catalog for one command. An explicit HTML or Markdown format uses JobKit's built-in renderer. An invalid explicit root fails.

What fails closed

  • Required work authorization, citizenship, active clearance, or no-sponsorship evidence is missing.
  • Required travel exceeds Nico's policy.
  • The posting is closed, expired, or outside the allowed role policy.
  • The resume index, manifest, or artifact digest changed.
  • A sendable manifest gate does not pass.

What the package proves

  • resume.pdf, resume.docx, or resume.txt contains the verified bytes.
  • resume-receipt.json records lane, version, selection reasons, and SHA-256 digests.
  • eligibility.json records hard-constraint evidence and any human override.
  • The tracker stores the same provenance tags.

Receipts do not expose the producer's absolute file paths.

The stop line

A prepared package is not an application. A tracked lead is not a send. Only Nico marks the application applied after he reviews and submits it.
